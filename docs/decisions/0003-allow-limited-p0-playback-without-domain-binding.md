# ADR 0003: ドメイン拘束なしの再生をP0招待試験だけに限定して許可する

- 状態: P0限定で採用
- 決定日: 2026-09-09
- Tracking: [Issue #16](https://github.com/rytich/play-cms/issues/16) / [Issue #35](https://github.com/rytich/play-cms/issues/35)

## 背景

play-cmsの一般公開要件は、Filmaの再生情報が動画単位・CMS指定期限内で、許可済みCMSドメイン以外では利用できないことである。一方、確認済みFilma公式仕様では、APIキー認証にドメイン制限があるもののJWT認証には適用されない。JWT更新後もCMSの絶対終了期限を越えない保証は未確認である。

この状態で一般公開すると、閲覧者が取得したJWTまたはプレイヤーURLを別ドメインへ持ち出し、有効期間内に再利用できる。長期間有効なFilma APIキーをブラウザーへ渡す方式は、動画限定の境界まで失うため採用しない。

一方、P0では3〜5名が非機密の専用テスト動画を操作し、CMSの導線とデプロイ方法を確認することが目的である。一般公開と同じ安全保証が整うまで全実装を止めるより、影響範囲を一動画・一環境・短期間へ閉じた試験を先行する。

## 決定

次の条件をすべて満たす場合だけ、ドメイン拘束なしの再生をP0招待試験環境で許可する。

- 対象は専用Cloudflare Worker/D1、招待した3〜5名、非機密の専用テスト動画一件だけとする。
- Filma APIキーはサーバー側で暗号化して保持し、response、URL、browser storage、ログへ出さない。
- ブラウザーへ渡すのは、対象動画の`mediafile_id`へ限定され、非null期限が`min(発行時刻+5分, CMS動画終了時刻)`以下のJWTを含む再生情報だけとする。
- `PLAY_CMS_P0_INVITE_PLAYBACK`は既定で無効とし、有効化時は`PLAY_CMS_P0_FILMA_FILE_ID`と一致する動画以外を拒否する。設定値と識別子をログへ出さない。
- CMSからJWT更新APIを呼ばない。ただし閲覧者がFilmaへ直接更新を試みる可能性は残るため、動画は漏えいしても業務・個人・顧客へ影響しない内容に限定する。
- 閲覧キー消費前にFilma grantを取得・検証し、取得失敗、期限不明、期限超過、動画限定不明、host不一致ではキーを未使用のまま残す。
- 招待試験終了後はWorkerを停止またはフラグを無効化し、一般利用へ転用しない。

Issue #35ではmockを使った製品実装を進められるが、実Filma再生と閲覧キー消費は既定で無効のままとする。実環境で動画単位と5分以下の期限を確認できない場合は、招待試験でも有効化しない。

## 一般公開の停止条件

Issue #16は一般公開に対して引き続きNO-GOとする。次を実APIまたはFilmaの保証で確認し、新しいADRで本決定を置き換えるまで、一般公開、本番動画、顧客データには使用しない。

- 許可済みCMSドメイン以外でJWT再生を拒否できること
- 既発行JWTと更新後JWTがCMSの絶対終了期限を越えて利用できないこと
- 期限後の再生情報、動画情報、サムネイル取得が拒否されること

## 影響

### 利点

- APIキーを公開せず、P0の閲覧導線・D1 migration・Cloudflare配置・3〜5名受入を先行できる。
- 例外がコードの既定動作や一般公開要件へ混入しない。
- Filma側の追加仕様を待つ間も、非機密データで操作上の問題を発見できる。

### 残るリスク

- JWTまたは再生URLは、有効期間内なら別ドメインで再利用される可能性がある。
- Filmaの更新APIにより、閲覧者が期限を延長できる可能性を現時点では否定できない。
- 環境変数や対象動画の設定ミスにより、意図しない動画を試験対象にする可能性がある。

これらは非機密動画一件、招待者3〜5名、専用環境、既定無効、終了後停止によって影響を限定する。一般公開の受入リスクとしては扱わない。
