## 2. テーマ方式の比較

| 方式                            | 長所                                              | 負担                                            | 判断                 |
| ------------------------------- | ------------------------------------------------- | ----------------------------------------------- | -------------------- |
| CSS変数＋ブランド設定＋静的ロゴ | 小さく、同じReact画面を保ったまま外観を変更できる | 変更時にファイル編集と再ビルドが必要            | **推奨・最初に実装** |
| Tabler等のUIキットを全面導入    | 多数の画面部品がそろう                            | 既存CSSとの調整、依存更新、不要機能の整理       | 今回は採用しない     |
| 管理画面でテーマを編集・保存    | 非エンジニアが変更しやすい                        | 保存API、権限、画像検証、プレビュー、復元が必要 | 利用検証後の別Issue  |

「簡単な変更」の初期範囲は、運用者が決められた設定ファイル・CSS・画像を差し替えて再ビルドすること。管理画面からの即時変更、任意テンプレート互換、ページビルダーは含まない。新たな有料サービスは要求しないが、Cloudflare無料枠での運用可否は既存の成果物サイズ・認証CPU等の測定ゲートで別途判断する。

## 3. 最小テーマ契約

### 変更できるもの

- サイト名、ロゴ、favicon。未設定・読み込み失敗時はサイト名テキストを表示。
- 背景、本文、補助文字、境界線、主操作とその上の文字、hover、フォーカスの色。
- 文字の種類、基本サイズ、余白、角丸。色と余白は各画面へ直書きせず共通値を参照。
- 同じブランドを管理・視聴・ログイン画面へ適用。管理画面は作業密度、視聴画面は読みやすさを優先し、必要な値のみ別指定可能。

成功・警告・エラーはブランド色と別の意味を持つ変数にする。色変更で区別を失わせず、ラベルとアイコンを併記する。テーマはナビ項目、権限、期限、警告文、DOMの意味・読み上げ順を変更しない。

### 提案ファイル構成（まだ作成しない）

```text
src/ui/
  brand.ts                 サイト名、ロゴ・faviconの同一サイト内パス
  themes/default.css       標準の意味別CSS変数
  themes/custom.css        運用者が変更する変数だけ。初期は空
  base.css                 フォーム・フォーカス等の共通スタイル
  components/              Brand、Button、Field、Notice、StatusBadge
  layouts/                 AdminLayout、ViewerLayout、AuthLayout
src/admin/                 既存の管理画面入口・管理画面部品
src/viewer/                視聴機能実装時に追加する画面
public/brand/              サイト公開を許可したロゴPNG/WebP・favicon
```

表示用設定は秘密を含まず、動画ID・APIキー・メール等の運用データと分離する。`default.css`→`custom.css`の順で静的に読み込む。`--play-color-bg`、`--play-color-text`、`--play-color-primary`、`--play-color-on-primary`、`--play-color-focus`、`--play-radius-control`等を初期契約とする。管理・視聴の差分は`data-surface="admin"` / `data-surface="viewer"`のスコープ内だけで上書きする。

差し替え手順は「ブランド設定を変更 → ロゴを差し替え → custom.cssの変数を変更 → 検証・ビルド → 配置」。元の設定・画像へ戻して再ビルドすれば復元でき、DB migrationは不要。キャッシュ更新を確認し、HTMLは新しい成果物を参照させる。初期は明色テーマ一種だけとし、暗色テーマ・実行中切替・テーマ選択DBは追加しない。

CSSは信頼されたリポジトリ管理者がレビューするビルド入力であり、安全なサンドボックスとは扱わない。ブラウザから任意CSS・HTML・JavaScript・URLを登録する機能は設けない。外部CSS、フォントCDN、`@import`、外部画像は使わず、システムフォントを使う。初期ロゴはPNG/WebPに限定し、任意SVGのアップロードやインライン挿入は設けない。`public/brand`に動画サムネイルを置かない。

## 4. 管理画面の情報設計

### 共通配置

- PC（960 CSS px以上）: 左240pxをナビ、右を本文。左上はロゴ＋「管理画面」、左下はログアウト。本文先頭にページ名、右側に主操作一つ。
- 小画面（960px未満）: 上部にロゴと「メニュー」ボタン。開閉領域は本文を押し下げる方式とし、複雑なモーダル・多重ドロワーは作らない。
- 主ナビは「動画」。Filma設定が使える段階でのみ「Filma連携」を追加。空のダッシュボード、全体キー一覧、未実装メニューは出さない。
- 動画内の操作は「基本情報」「閲覧用キー」の見出し付き領域にまとめる。深い階層やサイドバー内の重複キー管理を作らない。

### 画面と導線

| 画面                   | 入口・主操作                          | 表示と戻り先                                                                                        |
| ---------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `/admin/setup`         | 初回のみ管理者作成                    | 「初回セットアップ用トークン」の説明。通常ログインへのリンク。初期登録の既存サーバー制約を維持      |
| `/admin/login`         | メール・パスワードでログイン          | 管理者用であることを明記。成功後は動画一覧。管理者が未作成か否かを公開APIで列挙する機能は追加しない |
| `/admin/videos`        | 右上「動画を登録」                    | 動画タイトル・状態・公開期間・「編集」。初期は検索・ソート・集計を追加しない                        |
| 動画登録・編集         | 一覧から開き「保存」                  | Filma動画ID → タイトル → 説明 → 期間。下部に保存と一覧へ戻る。保存成功時だけ成功表示                |
| 動画内「閲覧用キー」   | 保存済み動画から開き「キーを1件発行」 | 未使用・使用済み・取消状態と日時。一度限りの生キー表示。取消操作は保存操作から離す                  |
| `/admin/filma`（後続） | ナビ「Filma連携」                     | 接続状態、APIキー入力・更新、接続確認。保存済み秘密の再表示は禁止                                   |

初期の登録・編集は`/admin/videos`内で行い、新規一覧APIやルーター依存を導入しない。画面切替時は見出しへフォーカスし、明示的な「一覧へ戻る」を置く。ブラウザ戻るで画面状態を復元する場合も閲覧用キーは履歴に含めない。個別編集URL・URL同期は別の必要性が生じた時点で検討する。

PR #20の先行管理モードでは「ローカル試作・公開と再生は無効」を常時明示する。状態表示は「未検証の下書き」で、公開・再生・共有URLコピーは表示しない。Filma連携・DRM・解析・アップロードのダミーボタンも出さない。

公開機能が承認・実装された後は、DB状態を増やさず`draft`/`published`とサーバー時刻から「下書き・公開前・公開中・終了」を表示する。日時にはタイムゾーンを明記し、開始を含み終了を含まない。管理者は終了動画の設定を管理できるが、視聴者向け表示を特例許可しない。

### 入力・破壊的操作

- 必須ラベルはプレースホルダーで代用しない。説明文はプレーンテキスト。
- 日時の不整合は入力欄に説明を付ける。入力エラー時は非秘密入力を保持して最初のエラーへ案内。
- 保存中・発行中は重複送信を抑え、失敗時は手動再試行を案内。失敗を空一覧や成功に見せない。
- 未保存変更からの離脱は確認する。保存後は「保存しました」をその場に表示。
- キー発行直後は「このキーは再表示できません」、コピーボタン、確認して閉じる操作を同一領域に置く。コピー失敗時は手動コピーを案内。閉じる・動画切替・ログアウト時に生キーを破棄し、localStorage・履歴・URLには保存しない。
- 発行結果が通信断で不明な場合は自動再発行しない。状態を再取得し、未使用キーの取消と新規発行を案内する。キーの総数制限は追加しない。
- 未使用キーの取消は対象を示す確認を挟む。動画削除や一括破壊操作は今回追加しない。

## 5. 視聴者画面の情報設計（後続実装）

管理画面のサイドバーを流用しない。上部にロゴ、ログイン済みなら「視聴できる動画」とログアウト。未ログイン時はログインへの導線。小画面も短い項目を折り返し表示し、多階層メニューを設けない。

| 画面・状態               | 表示・主操作                                                   | 次の導線                                                                                       |
| ------------------------ | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `/v/:publicId` 権限なし  | ブランドと閲覧用キー入力。動画のタイトル・説明・画像は出さない | 「キーを使って視聴」。既存アカウントは先にログイン可能                                         |
| キー消費前・未ログイン   | 一回限りであることと30分の一時視聴を説明                       | 「登録／ログインしてから使う」または「登録せずキーを使う」。確認のためだけの別ページは作らない |
| キー消費後・匿名         | プレイヤー、期限、一時視聴の残り時間、消えない登録案内         | 登録・ログイン後に同じ動画へ戻す                                                               |
| ログイン済み・視聴権なし | キー入力                                                       | 消費とアカウント紐付けをサーバーで同時に行い再生。登録警告は出さない                           |
| ログイン済み・視聴権あり | 視聴可能なら直接プレイヤー                                     | 追加コードを要求・消費しない。ライブラリに戻れる                                               |
| `/login` / `/register`   | 一列のフォーム、ログインと登録の相互リンク                     | 視聴から来た場合は権利引継ぎ成功後に元動画。それ以外は`/library`                               |
| `/library`               | 「視聴できる動画」、タイトルと期限、各「視聴する」             | 現在権利があり公開期間内の動画のみ。一覧自体はログイン必須                                     |

未ログイン時の警告文案:

> このキーは一度だけ使えます。登録せずに使うと、このブラウザでの一時視聴は最大30分です。再視聴するには、有効時間内に登録またはログインしてください。Cookieを削除したり別のブラウザに移ったりすると、一時視聴を引き継げません。動画の公開期限が先に来た場合は、その時点で終了します。

「二度と見られない」と断言せず、このキー・一時視聴からは復元できないと説明する。新しいキーの再配布を妨げる仕様にはしない。入力する値の呼称は「閲覧用キー」に統一し、アカウントの「パスワード」と区別する。

戻り先は同一サイト内の許可済み視聴経路だけに限定し、外部URLへリダイレクトしない。登録・ログインの成功と視聴権引継ぎの成功は別々に確認し、引継ぎ失敗を「保存しました」にしない。P0のメール所有確認・パスワード再設定未実装を維持し、存在しない復旧リンクは出さない。

## 6. 期限・権限と表示状態

| 状態                                     | 視聴者への表示                                                                    | サーバー・クライアントの条件                                                 |
| ---------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 読込中                                   | 汎用の読込表示                                                                    | 過去の保護コンテンツを仮表示しない                                           |
| 視聴可能動画0件                          | 「現在視聴できる動画はありません。配布されたURLから閲覧用キーを入力してください」 | 期限外動画の名前・件数を含めない                                             |
| キー無効・使用済み・対象なし・公開期間外 | 「このキーでは視聴できません。配布元へご確認ください」                            | 未認可ユーザーに理由を細分化して存在を漏らさない                             |
| 認可後に期限終了・非公開化               | 「現在この動画は視聴できません」                                                  | タイトル・説明・プレイヤー・画像を除去。動画固有情報なしで一覧への導線を出す |
| ログイン切れ                             | 汎用のログイン案内                                                                | 保護データを消し、認証後に権限を再判定                                       |
| 通信障害・503                            | 「現在処理できません。時間をおいて再試行してください」                            | 空一覧に偽装せず、秘密を含まないエラーのみ                                   |
| 試行回数制限・429                        | 待機と再試行の案内                                                                | サーバーの制限を尊重し、自動連打しない                                       |

期限判定は各APIでサーバーが実施する。画面タイマーは表示消去の補助であり認可には使わない。タブ復帰・再読込でも再検証し、期限到達時はプレイヤーを破棄する。保護データはページタイトル、OGP、非表示DOM、ブラウザ永続ストレージ、サービスワーカーキャッシュへ複製しない。保護レスポンスは既存方針どおりキャッシュ不可とする。

**P0ではサムネイル自体を取得・表示しない。** 将来追加する場合も一覧から消すだけでは不十分で、画像取得時に権限・期限を再検証する仕組みが必要。公開assetsや無期限の画像URLは不可。すでに配信した映像・画像をブラウザから完全に回収できるとは約束しない。Filma側の再生期限・発行済みトークンの確認が終わるまで、UIを変更しても実再生は有効化しない。

## 7. 読みやすさ・操作しやすさ

根拠は[WCAG 2.2](https://www.w3.org/TR/WCAG22/)と[Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)。準拠達成の宣言ではなく実装時の確認目標とする。

- 320・375・768・1280 CSS px幅、200%拡大、キーボードだけで主要操作を確認。小画面では表をラベル付き縦並びにし、主操作を横スクロール先へ置かない。
- 通常文字4.5:1、大きな文字3:1、操作部品・状態識別3:1のコントラストを目標。ブランド変更時も再確認。
- ボタン等の主操作は44×44 CSS px以上を設計目標とする。これは本CMSの目標であり、WCAG 2.2 AAの最低ターゲット寸法24pxと混同しない。
- 明確なフォーカス表示、本文スキップ、見出し階層、現在位置の通知を設ける。固定バーでフォーカス対象を隠さない。
- メニューの開閉状態を読み上げ可能にし、閉じるとトリガーへフォーカスを戻す。通知は支援技術にも伝え、自動で消える通知だけに依存しない。
- パスワードマネージャー・貼付けを許可し、適切なautocompleteを付ける。秘密情報をエラーへ反射しない。
- 動画は明示操作で再生し、音声の自動再生をしない。プレイヤー内のキーボード操作・字幕対応はFilma実連携時に別途検証する。

## 8. 実装順と受入条件

### A: 次の最小改善候補（本書承認後）

PR #20を基に、ブランド設定・変数抽出・共通部品・管理レイアウトを一つのIssueで改善する。既存のAPI、DB、データ、認証・公開拒否条件は変更しない。大規模なファイル再編はせず、重複がある表示部だけを抽出する。

1. ロゴ・サイト名と少数のCSS変数を変更するだけで、ログイン・一覧・編集の外観がそろう。元設定へ戻せる。
2. スマートフォンでログイン → 動画登録 → 保存 → キー発行・コピー → 取消まで操作できる。未保存・失敗・空状態も確認する。
3. キーを閉じる・ログアウト・再読込しても再表示されない。テーマ変更は既存動画とキーに影響しない。
4. 公開・再生・Filma通信は引き続き無効。ロゴ取得以外の外部通信や新規有料依存を増やさない。
5. 上記表示検証、既存の負系テスト、`pnpm verify`を記録する。アクセシビリティは既定テーマと差し替え例の両方で確認する。

### B: 視聴機能の実装時

Filma再生契約・公開ゲートの解消後、セクション5〜6の画面を機能と一緒に実装する。共通テーマだけを再利用し、使えない視聴画面を先に公開しない。

1. 未ログイン、ログイン済み権利なし、権利あり、引継ぎ成功・失敗の全導線を確認する。
2. キー二重使用と並行要求をサーバーが拒否し、UIだけの制御に依存しない。
3. 終了時刻ちょうど、非公開化、タブ復帰、直URL、ログアウト後の戻るで保護情報を返さない。
4. テスター3〜5名で、主要フローを補助なしで完了できる割合80%以上というP0目標を測る。迷った箇所をIssue化し、件数や時間を測るためだけの解析SDKは追加しない。
